KVP: Learning to Evict from Key-Value Cache

Learning to Evict from Key-Value Cache (KVP)

论文：arXiv；论文页注明 Accepted to ICML 2026 | PDF

一句话定位

KVP 不把 token 的重要性手写成 recency 或历史 attention，而把“在任意 cache budget 下该保留哪些 token”学习为一个离线训练、在线只读取 K/V/position 的 per-head 排序策略。

问题形式化

给定已处理 token 集合和 cache budget b，目标是选出 b 个 KV entry，使后续生成质量尽可能好。若每个 budget 都独立做组合选择，在线代价很高且不同 budget 的集合可能互相矛盾。KVP 先设计具有唯一性和嵌套性的 reward：最优的 b 个保留集合是 b+1 个集合的子集。这样问题转化为学习一个全序 ranking，top-b 即是任意 budget 的解。

这一步是论文的核心建模选择：它让一个排序策略能覆盖动态 cache 压力，而不是每次重新训练/搜索。

策略与训练

每个 attention head 对 token i 的特征是 (K_i, V_i, position_i)。一个小 MLP 输出分数；通过基于分数的随机排列策略采样 token 排名，利用 Gumbel-Sort 实现并行采样。策略不读取未来 token、在线 attention score、query embedding 或模型内部额外状态。

训练阶段使用预先计算的生成 trace 和 RL reward。reward 衡量一个排序在多种 cache budget 下的整体效用，因此不是只为某个固定压缩率过拟合。论文采用 per-head agent：不同 head 可保留不同 token，而不是强迫整个 layer 使用同一个全局稀疏掩码。

在线阶段只需在 memory refresh 时对已有 K/V 打分、排序和截断；不修改基础 LLM 权重或 attention 结构，也不增加额外模型推理。

实验读法

主评估使用 Qwen2.5-7B-Chat，并在附录扩展到 Phi-4-14B；覆盖 RULER 长上下文、OASST2-4k 多轮对话，以及 LongBench passage retrieval 等。论文强调 KVP 在不同 budget、到 128K context 的场景中优于启发式基线，即便部分基线可访问更特权的 query-specific 信号。

复现时应区分三个量：压缩后质量、内存峰值、memory refresh 的额外耗时。KVP 的优势是 quality-aware ranking，不保证其排序/refresh 本身一定比极简 LRU 更便宜。

对 codesign 的作用与边界

KVP 不知道 workflow、Agent、工具等待或未来调用；它回答的是“已经决定要缩 cache 时，cache 内部哪些 token 该保留”。因此它适合成为分层策略的局部算子：上层 TOPAS/PBKV/SAGA 决定哪个 session/prefix 值得占空间，下层 KVP 在该 prefix 内做 token 压缩。

局限也由此明确：token future utility 不等于 workflow future reuse；离线 trace 的任务分布、模型层数和上下文长度与线上偏离时，需要重新验证泛化和 refresh 开销。
