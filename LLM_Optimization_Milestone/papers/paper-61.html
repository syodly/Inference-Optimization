Leyline: KV Cache Directives for Agentic Inference

Leyline：KV Cache Directives for Agentic Inference

Bole Ma、Jan Eitzinger、Harald Koestler。arXiv:2606.01065v1，2026-05-31；截至 2026-10-14，已核查页面未标注会议接收信息。

问题与定位

Agent 主动删除失败工具输出、替换旧调查内容或压缩历史时，普通请求接口只得到编辑后的 token 序列，编辑位置后的连续前缀失效。Leyline 提供显式编辑操作，将“编辑什么、要求什么保证”交给 serving；不是让所有移动后的 KV 自动精确有效。

编辑契约与执行

指令包含起止 token 位置、替换 token 和语义模式。amortize 删除指定区间、计算替换部分，并校正后续位置；保留后续状态已经吸收的旧信息。forget 要求旧内容不继续通过缓存影响生成，沿用截断后重新 prefill。二者保证不同：位置修正不等于对编辑后的文本完整重算，也不等于遗忘。

主要 kernel 针对 MLA：对位置相关 K 做 RoPE 增量旋转，保留后续位置无关分量与 V；接入 radix 缓存使编辑后的状态可继续匹配。GQA／MHA 扩展讨论边界重算，不能视为 Mistral 的已验证实现。

实验证据

证据 场景 结果与边界
splice 机制 约 17K 输入、SGLang、并发 1／4／8／16 相比标准 radix，回放命中提升 11.2 个百分点；延迟最高减少 241 ms
上下文策略 debug-gym mini_nightmare，8 任务、4 seeds 截断策略 solve rate 提升 14.3 个百分点；与机制实验是两条证据

不能将这两个结果写成同一次真实 coding 部署同时获得的收益；bf16 旋转误差、模型敏感性与长期编辑仍需检查。

与当前方向的关系

HEAR 统一工作流与引擎的交互契约，Leyline 将其中的上下文编辑具体化。对我们的启发是显式记录历史版本与编辑语义，再分别评价精确继承、近似修复和重新计算。版本或内容 ID 负责定位，不证明 KV 因果有效性。
