    联网调查 · 2026-10-29 · 以官方资料为依据

    不需要某个特定模型，但“能调用”与“会主动委派”是两件事

    01 / 任务
    独立调查更容易并行

    多个对象、多个证据来源或多个互不依赖的检查，需要各自搜索、判断、再汇合。仅仅文件多，或任务很长，不保证值得开子 Agent。

    02 / 模型
    委派能力取决于具体工具与编排

    Qwen27B 已在 ODR 主管工具面产生实际委派；DSH 多组默认或通用建议运行仍未产生子 Session。这说明模型可用这类能力，不代表在任意工具面下都会主动选择。

    03 / Harness
    创建、后台运行、消息汇合都要支持

    模型输出一个 Agent 名字不会产生新请求。Harness 必须提供委派工具、执行提供方和后台生命周期；并发额度、工具安全规则及提示决定实际行为。

    优先调查的场景为什么可能产生并行 Agent 请求只给目标的示例任务证据性质
    多对象、跨来源深度调查各对象有独立搜索与证据链，主 Agent 汇总比较；子任务自身需要多轮工具与推理。比较几家推理服务的部署约束、计价与数据策略，逐项核对官方出处，标出缺失信息。Anthropic 生产研究系统；示例任务为本次建议，未实测。
    代码库审查、跨模块理解安全、性能、测试等检查可独立阅读；涉及同一文件修改时，依赖和冲突会收窄并行。审查这个服务的鉴权、重试和数据一致性，给出带文件位置的风险及复现依据。Claude Code 的委派用法；不是所有 coding 都适合并行。
    宽范围检索、独立证据核验不同候选对象需要各自筛选、查证，再去重汇合；工作分量与难度可动态变化。找出符合给定条件的机构，为每项条件列出证据，并解释排除的候选。Kimi 的 WideSearch / Agent Swarm；依赖对应系统与训练。
    模型大小、参数与钩子：核对后的具体结论和来源

    没有可靠的“低于多少 B 就无法多 Agent”门槛。并行是多次模型调用的执行方式，同一组权重可以服务多个 Session。模型大小可能影响拆分、委派和汇合的质量；worker 能完成局部任务，不等于它能做好 orchestrator。Qwen-Agent 文档明确支持 parallel function calls，但这不证明自主子 Agent 编排。

    生产系统也会显式教模型如何委派。Anthropic 报告在系统提示中加入复杂度与委派规则；Kimi 的 PARL 训练专门处理“有并行容量仍退回串行”的现象。后者说明并行编排训练有价值，不证明只有该模型可做，也不代表下载权重就自动具备其完整产品运行环境。

    检查项本次固定版本 DSH 的事实它能做什么
    服务＋provider＋工具只挂 SubagentManager 不够，还要挂执行提供方和模型可见的委派工具；本实验均已可见。使委派成为可执行动作，不能强迫模型选择它。
    maxDepth / maxActiveSubagents默认 1 / 8；前者允许直接孩子，后者是每棵 activation 树的上限。允许或限制委派。没有委派尝试时，增大上限不会自动产生孩子。
    maxParallelToolCalls默认 10；只有 isConcurrencySafe 明确为真的调用可重叠。read 可并行，edit / write / bash 为互斥。调节已提出的工具如何执行；与子 Agent 的模型并发数量不同。
    模型 API、解析器现有 qwen3_xml 工具解析与 auto tool choice 已工作，实际请求未设置 parallel_tool_calls。将生成内容解析成动作；API 支持一个字段不等于模型将自动委派。
    钩子现有生命周期事件可记录；agent/request 可接派发策略。基线委派不需要新钩子。记录与未来调度可使用钩子，不能暗中生成孩子后声称自然行为。

    本轮已补齐这些对照：原生、放宽 workflow、通用委派建议、low / medium / xhigh 与 Agent Teams 的18组记录均已归档；其中失败单列。同一 Qwen 在原生 ODR 主管工具面出现真实委派，GPT Researcher 则由程序创建递归实例。没有预写查询或 Agent 数，不据此给出通用的自然委派概率。
