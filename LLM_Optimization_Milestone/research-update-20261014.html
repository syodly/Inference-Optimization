当前研究进展

研究从动态图调度和工具等待，推进到多轮 coding 的 KV 复用，再转向上下文变化与引擎状态的协同。以下区分已测结果、论文启发和待验证选题。

进展 已获得的证据 当前边界
CacheBlend 官方场景复现 Mistral 与 MuSiQue、WikiMQA、SAMSum 的公开实验链路已运行 不等同于完整 coding workflow 质量
CacheWise 轨迹构造 80 会话／11,012 请求；后续取 8 个完整会话／757 请求 脱敏长度与公开文本组合是合成负载；非原任务正确率数据
多轮自由生成 Mistral TP4、32 GiB GPU KV；输出长度固定，内容自然生成 两组回答进入各自历史，后续输入可能分叉
KV 双份状态 GPU 保留会话修复状态；CPU 保留独立块素材 修复前缀可沿用但非精确；额外存储与构建计入成本

平均／P95 TTFT 34.73／82.83 s 42.97／103.06 s
连续前缀命中 32.90% 29.92%（精确 12.48%＋修复 17.44%）

独立 KV 构建 — 1329.9 s

两组使用 256K 配置窗口、未缩放 RoPE；这只说明执行长度覆盖，不能证明模型在该长度的任务能力。混合组额外使用 32 GiB CPU 独立块缓存，当前结果不是同总存储预算的比较。

混合组 prefill 调用减少 436.1 s，但额外构建等成本使总耗时增加 21.58 min。合计覆盖率不是免计算率。相对原生输出的全文 token F1 为 0.8916，完整序列一致率 66.58%；这是输出一致性，不是代码正确率。旧 ForcedTokens 回放结果不用于质量结论。现有结果尚不能区分算法必需成本与适配可避免成本。

近期论文带来的方向调整

工作 当前吸收的要点
HEAR 工作流意图与引擎状态双向反馈；消息类别应落到实际决策回路
Leyline 显式编辑区间与语义模式；低成本继续执行与彻底遗忘分开
KVTether／EfficientAgent 生命周期与容量竞争决定缓存能否活到下一次使用
CADOC／SmoothAgent 上下文转换的时机、版本与构建不能只由后端被动处理
Request Order Matters／MemTrace 缓存经历、内容版本和证据有效性需分别核验

候选 topic：尚未确认为创新点

1. 面向多轮 Agent 工作流状态的 KV 生命周期协同管理

  1. 将工具等待、会话继续与任务结束等工作流事件关联到引擎 KV 状态。
  2. 联合评估保留、卸载、恢复和回收，工具进度只作为信号，不单独以预取作为贡献。
  3. 在相同容量下比较有效历史命中、搬运、重算与 workflow 完成时间，核对 HEAR、KVTether、PBKV 等重叠。

2. 面向 Agent 上下文编辑的 KV 失效分析与版本感知复用

  1. 识别追加、替换、删除、压缩和回退，分析编辑位置与 KV 失效及复用机会；长度变化不能代替编辑类型。
  2. 由编排层传递版本与编辑语义，区分精确继承、待修复和失效状态；版本 ID 不证明因果有效性。
  3. 用受控真实文本比较重算量、TTFT 与输出保真度，有任务测试时评价成功率；核对 Leyline、PatchKV 和 Retire 的覆盖。

下一步先确认真实轨迹能提供哪些编辑与生命周期证据，再选定一种变化和可证伪假设；不把“组合更多机制”作为创新性理由。
