# 固定Session窗口与回流排序组合对照（待实测）

v017静态历史预算均值132.14秒、P95为208.81秒，无额外测量的回流排序为134.99/211.07秒；前者仅生成63285个输出token，后者64859个，不能把全部差异归给计账。另一个对照问题是预算策略本身已经优先回流，而原先的固定Session窗口仍按请求就绪次序执行，两者同时改变了额度类型和排序。新增session_return把固定Session窗口与完全相同的回流、汇总优先及120秒老化组合，保留全部必做工作，并省去不需要的额外长度测量。v020工具等待轮次加入窗口18组合，v021冻结混合输入和生成量后比较窗口12/18组合。只有在这些简单组合、调优请求数量与短输入排序之外仍保留收益，才有理由继续研究历史大小或引擎状态的独立价值。本版本只增加待执行强基线，不宣称新机制有效，也不把高命中率替代任务质量和耗时。

复现参数：`--policy session_return --cap 24 --session-cap 18 --starvation-seconds 120`。代码加入`stage-v2`，在v017结束后与执行语义和账本第二版一起部署。v020现在7轮，v021现在11轮；每轮独立计时与记录。
