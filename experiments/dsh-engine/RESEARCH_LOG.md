# 官方 DSH 部署、验收与研究边界记录

## dsh-deploy-v001 · 2026-10-29 · 官方发行版与独立环境

本轮将官方 DeepSeek Harness 部署到 songprojgpu1 的独立 dsh-lab，纠正此前“没有完整源码”和将自建框架近似称为 DSH 的表述。安装固定发行包 0.2.1-rc.2，并保存对应源码标签与提交；更新的 master 快照另存，不混同实际运行版本。服务器原 Node 过旧，使用独立 Node 24.22.2，不改系统环境。复用此前经 ModelScope 下载校验的 Qwen3.8-27B 权重和 vLLM 环境，在确认 GPU 0/1 空闲后启动独立接口，加入 Qwen XML 工具调用解析。原实验 STOP 保持不变，不恢复性能批次。本轮没有修改官方源码，也没有植入新调度器；成果是建立可追溯的真实系统基线，安装成功不作为性能或创新证据。

配置：[qwen.patch.yml](qwen.patch.yml)、[start_engine.py](start_engine.py)；来源：[source.json](evidence/deployment-20261029/source.json)。

## dsh-accept-v001 · 2026-10-29 · 原生委派与真实模型调用

本轮在官方 CLI 中以 Qwen 执行真实验收。先验证自动工具参数解析和普通对话，再使用公开 HotpotQA 的一题，把十篇原始资料分成三份文件，要求父 Agent 创建三个原生子 Agent。原生会话日志证明每个孩子各读一个分片、发送报告、正常结束，无嵌套委派、网络访问或工具错误；父 Agent 接收报告及完成通知后汇总。模型调用实际为父八次、各子三次，共十七次，另有一次标题生成，不能沿用旧固定十调用 DAG 的账目。最终答案实体与隐藏标签相符，但十七世纪的时间界定含间接推断，单题不代表准确率。全部主任务请求、响应、prompt、工具参数、原生事件和资料均已归档。这只能证明原生多 Agent 路径可运行，尚未证明共享负载痛点或调度收益。

证据：[验收报告](evidence/deployment-20261029/acceptance/report.json)、[完整原始证据](evidence/deployment-20261029/deployment-20261029-raw.tar.gz)。

## dsh-accept-v002 · 2026-10-29 · Web、Shell 与定位复核

本轮通过临时 SSH 隧道打开官方 Web，完成进程 token 与浏览器会话的登录交换，页面 HTTP 200、无脚本错误，界面显示本地 Qwen 及 low reasoning。复验不发送模型 prompt，检查后关闭隧道；登录 token 不写入仓库。另让官方 CLI 真正调用一次 Bash 输出常量，工具和最终回复均成功，确认不只是文件读取可用。源码复核发现 activation 容量、完成通知、workflow 并行汇合和 vLLM 优先级本已存在，不能作为我们的贡献。研究建议收敛为工作流已知依赖与动态引擎压力共同决定合法推进顺序；先比较原生 subagent、workflow 和简单静态策略，再判断是否值得设计新机制。当前留存官方服务供后续使用，GPU 用于模型服务，旧实验继续暂停。

证据：[Web 报告](evidence/deployment-20261029/web/report.json)、[官方界面](evidence/deployment-20261029/web/official-dsh-web.png)、[研究定位与固定版本源码](RESEARCH_POSITION.md)。Shell 的完整日志随原始证据压缩包归档。

## dsh-e1-setup-v001 · 2026-10-29 · 八题应用与可比较环境

用户最新要求将范围限定为已经完成过的最小组，因此本次选择v004的八题HotpotQA，只比较直接派发、固定12和实际压力12，不恢复原二十题共享负载或v025。新增科研应用插件，利用官方Agent与Workflow引擎执行三分片研究，BM25沿用旧纯工具函数，旧Harness不实例化；应用的每题八次调用比旧组多一次父规划，明确禁止跨框架归因。部署服务原先没有缓存复位路由，本轮启用VLLM_SERVER_DEV_MODE后重启自己的引擎，其他模型/GPU/引擎参数保持一致，三轮都在这个新进程完成。所有条件统一2048输出上限、低推理强度和温度零，每轮确认空闲并真实复位前缀缓存。隐藏答案只在离线分析读取，输入文件无答案字段。

## dsh-e1-calibration-01 · 2026-10-29 · 独立功能校准与预热

先用原校准组第一题检查DSH的完整路径，不纳入三条件性能表。父Agent调用科研工作流工具，官方引擎并行创建三个子Agent；每个子Agent真实生成检索参数、执行一次BM25并提交证据，父Agent等待全部结果后回答。四份原生会话日志与八个接口响应一一对应，三个分片均覆盖，模型、工具、输出长度及派发许可审计通过，耗时36.16秒。最终预测Maria Shvetsova缺少标签中的Chief Detective，严格EM为零、F1为0.667，保留原始评分而不冒充完全正确。随后仅修正工作流事件监听的双参数记录，使成员信息完整；执行语义和prompt未改变。真实模型的后端生成计数与响应解码量2433一致，证明链路不是文本模拟。

证据：[校准汇总](results/e1-small-20261029/dsh-e1-calibration-01/summary.json)、[完整原始记录](evidence/e1-small-20261029/dsh-e1-calibration-01-raw.tar.gz)。

## dsh-e1-small-native · 2026-10-29 · 直接派发

第一轮同时提交八个原校准任务，保留每题三条必做分支，由官方DSH原生循环直接推进。八题全部完成，32个Agent、64次模型调用与24次BM25均通过独立原生日志和实际接口审计；实际解码20445token，与引擎生成计数增量一致，无工具错误、截断或悬挂许可。平均完整任务48.43秒，P95为55.59秒，整轮58.29秒，包含Host启动和所有等待。严格EM为0.500，答案F1为0.815，来源标题召回0.875。引擎运行峰值24，等待峰值8，KV使用峰值42.89%，没有抢占；直接派发的前端等待接近零。这是本组基线，不把一轮排队直接视为可优化痛点，也不与旧七调用程序的绝对速度比较。

证据：[本轮汇总与审计](results/e1-small-20261029/dsh-e1-small-native/summary.json)、[完整原始记录](evidence/e1-small-20261029/dsh-e1-small-native-raw.tar.gz)。

## dsh-e1-small-fixed12 · 2026-10-29 · 静态在途上限

第二轮只将就绪模型请求的全局在途上限设为12，FIFO派发，保持DSH应用、数据、分支和推理配置一致，前端等待仍计入根任务。八题、32个Agent、64次调用和24次检索完整通过审计，无截断或模型错误，实际20707个解码token与引擎计数一致。平均任务60.70秒，P95为69.01秒，整轮70.52秒；每调用平均增加5.57秒前端等待，后端排队峰值降为零，KV峰值20.93%，仍无抢占。因此排队减少未换来任务更快。EM为0.625、F1为0.908，部分答案比直接轮更完整；这是单轮生成变化，不能归为静态上限稳定改善质量。这里只测原最小组的12，不据此宣称已经扫描到最优并发设置。

证据：[本轮汇总与审计](results/e1-small-20261029/dsh-e1-small-fixed12/summary.json)、[完整原始记录](evidence/e1-small-20261029/dsh-e1-small-fixed12-raw.tar.gz)。

## dsh-e1-small-pressure12 · 2026-10-29 · 实际压力反馈

第三轮在相同12上限下启用真实引擎反馈，每250毫秒读取等待数与KV使用，沿用原阈值收缩后续派发。八题全完成，32个Agent、64次模型调用、24次检索通过审计，实际20797个解码token与后端计数完全一致，无错误、截断或悬挂许可。平均60.47秒，P95为76.23秒，整轮82.11秒；EM为0.500、F1为0.783。等待峰值零、KV峰值24.03%，反馈收缩准入数零，实际一直执行固定12。因此与静态轮的均值微差不是反馈收益，长尾和答案变化也不能用未发生的收缩解释。三轮仅一次独立重复、文本没有冻结，当前只能报告此小组未看到限流/反馈收益。按最新范围到此结束，不衔接更大的GPU实验。

证据：[本轮汇总与审计](results/e1-small-20261029/dsh-e1-small-pressure12/summary.json)、[完整原始记录](evidence/e1-small-20261029/dsh-e1-small-pressure12-raw.tar.gz)、[三轮比较与实际答案案例](notes/e1-small-20261029.md)。
